# 个人博客系统 技术方案

> 版本：v1.0 ｜ 日期：2026-09-26 ｜ 关联文档：`doc/PRD.md`（需求有歧义时以 PRD 为准）

## 1. 技术选型

一句话概括：**一个 Next.js 全栈项目，前台后台住在同一个应用里，数据存成一个 SQLite 文件。**

### 1.1 选型清单

| 部分 | 选型 | 说明 |
| --- | --- | --- |
| 应用框架 | Next.js 16（App Router）+ React 19 + TypeScript | 一个项目同时管页面和服务器逻辑，不用维护前后端两个仓库；TS 让字段名写错当场报错 |
| 样式 | Tailwind CSS v4 + @tailwindcss/typography | 样式直接写在标签上；typography 负责 Markdown 正文的排版（标题、引用、代码块默认样式） |
| 数据库 | SQLite（libsql 驱动） | 整个库就是一个文件，零运维，备份即复制文件；个人博客体量完全够用 |
| 表结构管理 | Drizzle ORM | 用 TS 代码描述表结构，类型安全，改动可追溯 |
| 登录 | bcryptjs + 自建 HMAC 签名 Cookie | 密码只存哈希、原文永不落库；登录后浏览器持有一张"盖章门票" |
| Markdown 渲染 | react-markdown | 把 Markdown 原文转成网页内容 |
| 表单校验 | zod | 一套规则前后端共用 |

**不选别的的理由**：不装 MySQL/Postgres——一个人写博客，SQLite 足够，部署时不用额外装数据库服务；不引入 NextAuth 等登录框架——只有一个账号、一种登录方式，自签 Cookie 更简单可控、出问题好查。这套组合是上一版验证通过的技术栈，已知问题都有记录，直接沿用规避。

### 1.2 环境变量（`.env`）

| 变量 | 用途 |
| --- | --- |
| `ADMIN_USERNAME` | 管理员账号 |
| `ADMIN_PASSWORD` | 管理员密码（**只在 seed 时使用**，落库前会哈希；改完必须重跑 seed 才生效） |
| `SESSION_SECRET` | Cookie 签名密钥 |

## 2. 架构规范

1. **前台后台同应用，但泾渭分明**
   `/`、`/posts`、`/about` 是访客只读区；`/admin/*` 是博主区，一律要求登录。
   **草稿隔离只有一处把关**：所有面向访客的查询都必须带「已发布」条件，不设第二条路径。

2. **读数据在页面里查，写数据走 Server Action**
   后台表单提交不定义 REST 接口，直接调用服务端函数，少一层接口定义与类型对齐成本。

3. **登录状态只能有一处"说了算"**
   中间件只做粗筛（有没有 Cookie），后台门禁 layout 做严格校验（签名是否有效）。
   两处判断标准不一致会互相踢皮球，把浏览器带进无限重定向。正确分工：中间件对登录页直接放行，已登录跳转由登录页自己验签后决定。

4. **PRD 没写的不加**
   不做标签、分类、分页、搜索。有疑问先查 `doc/PRD.md`。

## 3. 项目目录结构

```
newblog/
├── app/                          # 页面（目录名 = 网址，Next 自动生成路由）
│   ├── layout.tsx                # 全站根布局：字体、全局样式
│   ├── page.tsx                  # 首页（文章列表）
│   ├── posts/[slug]/page.tsx     # 文章详情（动态地址段）
│   ├── about/page.tsx            # 关于我
│   ├── not-found.tsx             # 404 页
│   └── admin/
│       ├── login/page.tsx        # 登录页 ← 故意放在门禁外面
│       └── (protected)/          # 括号是"路由组"，不进网址，只用来加门禁
│           ├── layout.tsx        # 后台外壳：侧边栏 + 验票逻辑
│           ├── page.tsx          # 仪表盘
│           └── posts/
│               ├── page.tsx           # 文章列表
│               ├── new/page.tsx       # 新建文章
│               └── [id]/edit/page.tsx # 编辑文章
├── actions/                      # 服务器函数：登录/登出/文章增删改
├── components/                   # 复用组件：页头、文章卡片、统计卡、删除确认框…
├── lib/
│   ├── db/index.ts               # 数据库连接（全局单例）
│   ├── db/schema.ts              # 表结构定义
│   ├── session.ts                # 发门票 / 验门票
│   ├── slug.ts                   # 由标题生成网址后缀
│   ├── action-state.ts           # 表单状态常量（"use server" 文件只能导出 async 函数，常量必须外置）
│   └── site-content.ts           # 站名、页脚、"关于我"静态文案
├── doc/                          # PRD.md、tech.md
├── scripts/
│   ├── seed.ts                   # 初始化：建表 + 写入管理员账号
│   ├── e2e.ts                    # 端到端验收脚本
│   └── check-responsive.ts       # 三档宽度响应式检查脚本
├── proxy.ts                      # 中间件（Next 16 已由 middleware.ts 改名，用旧名会构建告警）
├── next.config.ts                # 需配置 serverExternalPackages: ["@libsql/client", "libsql"]
├── drizzle.config.ts             # dialect: "turso"（走 @libsql/client，不需要 better-sqlite3）
└── .env
```

两个"看起来怪但有讲究"的地方：

- **登录页必须待在门禁外**：`admin/login/` 与 `admin/(protected)/` 是兄弟目录。若登录页也套上"先登录"外壳，就会变成"要登录才能打开登录页"，与门禁互相重定向。
- **`proxy.ts` 不是笔误**：Next 16 把中间件文件从 `middleware.ts` 改名为 `proxy.ts`（默认导出函数）。

## 4. 路由设计

| 网址 | 页面 | 谁能看 | 说明 |
| --- | --- | --- | --- |
| `/` | 首页 | 所有人 | 已发布文章按发布时间倒序 |
| `/posts/{slug}` | 文章详情 | 所有人 | 草稿或不存在的地址 → 404 |
| `/about` | 关于我 | 所有人 | 静态文案 |
| `/admin/login` | 登录 | 所有人 | 已登录访问则自动跳仪表盘 |
| `/admin` | 仪表盘 | 仅博主 | 总数 / 已发布 / 草稿 三张统计卡 + 最近文章 |
| `/admin/posts` | 文章列表 | 仅博主 | 支持按状态筛选 |
| `/admin/posts/new` | 新建文章 | 仅博主 | 标题 + 正文 + 状态 |
| `/admin/posts/{id}/edit` | 编辑文章 | 仅博主 | 回填已有内容 |
| 其他任意路径 | 404 | 所有人 | 兜底 |

## 5. 数据库 Schema

**只需要两张表**——"关于我"是静态文案（PRD 明确不做后台编辑），不占表。

### posts（文章表）

| 字段 | 类型 / 约束 | 说明 |
| --- | --- | --- |
| `id` | 整数，自增主键 | 内部编号 |
| `title` | 文本，非空 | 标题 |
| `slug` | 文本，非空、唯一 | 网址后缀，由标题自动生成；支持中文，标点会被去掉，重名自动加序号（如 `-2`） |
| `content` | 文本，非空 | Markdown 正文原文 |
| `status` | 文本，非空，默认 `draft` | 取值仅 `draft` / `published` |
| `published_at` | 时间，可空 | **首次转发布时写入**，之后编辑不改动；首页排序与详情页日期都用它 |
| `created_at` | 时间，非空 | 创建时间 |
| `updated_at` | 时间，非空 | 最后修改时间 |

> `slug` 的编辑策略：文章还是草稿时，改标题会同步更新地址；一旦发布过（`published_at` 非空），地址固定不再变化，避免已分享的链接失效。

### users（管理员表）

| 字段 | 类型 / 约束 | 说明 |
| --- | --- | --- |
| `id` | 整数，自增主键 | |
| `username` | 文本，非空、唯一 | 管理员账号 |
| `password_hash` | 文本，非空 | 密码哈希，原文不落库（来源 `.env`，由 seed 写入） |

## 6. 实现步骤

七步推进，每步都有当场可验证的产物。

**第 1 步 · 地基**
初始化 Next 项目、配好 Tailwind、接通数据库、定义两张表、写 seed 脚本灌入管理员。
→ 验证：`npm run seed` 后能查到管理员记录。

**第 2 步 · 前台只读三页**
首页列表 → 文章详情 → 关于我 → 404。此时尚无后台，先用脚本塞几篇测试文章。
→ 验证：浏览器三页均正常，草稿不出现。

**第 3 步 · 登录闭环**
登录页、发/验门票、后台门禁、退出登录。这步最容易出重定向死循环，严格按"中间件粗筛、门禁 layout 验签、登录页放行"三层分工。
→ 验证：未登录访问 `/admin` 跳登录；登录后能进；退出后回到登录页。

**第 4 步 · 后台外壳 + 仪表盘**
侧边栏导航 + 三张统计卡 + 最近文章列表。
→ 验证：统计数字与数据库真实条数一致（断言与真实值比对，不写死数字）。

**第 5 步 · 文章管理**
列表（含状态筛选）→ 新建 → 编辑 → 删除（二次确认，提示中带文章标题）。保存成功回列表页。
→ 验证：完整走一遍「写草稿 → 发布 → 前台可见 → 改回草稿 → 前台消失」。

**第 6 步 · 响应式打磨**
按 `doc/PRD.md` 4.1 的对照表，在 375 / 768 / 1440 三档逐页过。重点两处：后台侧边栏变抽屉、后台表格变卡片堆叠。
→ 验证：三档下无横向滚动、按钮均可见可点。

**第 7 步 · 验收**
两个自动化脚本：`npm run e2e`（全流程，按标题/aria-label 精确定位元素，禁用"第一个按钮"这类模糊选择器，避免误删真实文章；统计类断言与库中真实值比对）、`npm run check:responsive`（三档宽度布局检查）。最后 `npx tsc --noEmit` 与 `npm run build` 全绿。
