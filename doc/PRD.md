# 个人博客系统 PRD

> 版本：v1.0 ｜ 日期：2026-09-26 ｜ 状态：待开发

## 1. 产品概述

### 1.1 项目名称

**newblog** —— 个人博客系统

### 1.2 项目目标

- 为博主提供一个完全自有的内容发布空间：文章存在自己的库里，不受第三方平台规则与算法约束
- 为访客提供无需注册、打开即读的轻量阅读体验
- 博主通过独立的管理后台完成全部内容维护，过程中不需要接触代码或数据库

### 1.3 核心价值

- **内容自持**：文章归属博主自己，随时可导出、可迁移
- **读写分离**：访客端只读且极简；管理端能力完整但仅博主可见
- **零门槛发布**：登录后台 → 写 Markdown → 发布，全流程可视化，不碰命令行
- **草稿保护**：未完成的内容可先存为草稿，不会提前暴露给访客

## 2. 目标用户

| 角色 | 描述 | 使用场景 | 核心诉求 |
| --- | --- | --- | --- |
| 访客（读者） | 通过分享链接或搜索进入的任何人，无需注册登录 | 浏览文章列表、阅读正文、了解博主 | 打开快、排版易读、手机上也舒服 |
| 博主（管理员） | 站点唯一所有者，持有唯一的管理员账号 | 撰写、编辑、发布、删除文章，查看文章统计 | 登录安全、操作路径短、不会误删 |

角色边界：

- 访客只能看到「已发布」的文章，草稿对访客完全不可见（即便直接访问其地址也看不到）
- 后台所有页面仅博主可访问，未登录一律跳转登录页
- 全站只有 1 个管理员账号，不提供注册、多用户、权限分级

## 3. 功能需求

### 3.0 页面总览

| 端 | 页面 | 路径 | 访问权限 |
| --- | --- | --- | --- |
| 用户端 | 首页 | `/` | 公开 |
| 用户端 | 文章详情页 | `/posts/{slug}` | 公开（仅已发布文章） |
| 用户端 | 关于我 | `/about` | 公开 |
| 用户端 | 404 页 | 任意不存在路径 | 公开 |
| 管理后台 | 登录页 | `/admin/login` | 公开（已登录则跳仪表盘） |
| 管理后台 | 仪表盘 | `/admin` | 仅博主 |
| 管理后台 | 文章管理列表 | `/admin/posts` | 仅博主 |
| 管理后台 | 新建文章 | `/admin/posts/new` | 仅博主 |
| 管理后台 | 编辑文章 | `/admin/posts/{id}/edit` | 仅博主 |

### 3.1 用户端

#### 3.1.1 首页

**功能描述**：站点门面，展示博主的全部已发布文章，按发布时间由新到旧排列。访客在这里扫读标题与摘要，决定点开哪一篇。

**页面组件**：

- 站点页头：站名（点击回首页）+ 导航项「首页」「关于我」，当前页高亮
- 文章卡片（列表项）：文章标题、摘要（从正文截取约 80–120 字）、发布日期
- 卡片整块可点击 → 进入该文章详情页
- 页脚：版权信息
- 空状态：尚无已发布文章时显示占位文案（如「还没有文章」）

**交互与规则**：

- 只显示「已发布」文章，草稿不出现、不占位
- 排序：按发布时间倒序；发布时间相同则按创建时间倒序
- 列表不分页（本期不包含分页、搜索、标签与分类筛选）

#### 3.1.2 文章详情页

**功能描述**：阅读单篇文章的完整内容。

**页面组件**：

- 站点页头（与首页一致）
- 文章标题
- 发布时间
- 正文：Markdown 渲染，需正确支持标题、段落、列表、引用、代码块、行内代码、图片、链接、分割线
- 返回入口：页头站名，以及正文末尾的「返回首页」链接
- 页脚

**交互与规则**：

- 只有「已发布」文章可访问；草稿或不存在的地址一律展示 404 页
- 正文中的代码块使用等宽字体，可横向滚动，不撑破页面布局
- 正文图片自适应容器宽度，不溢出

#### 3.1.3 关于我页

**功能描述**：介绍博主本人，建立读者信任与联系渠道。

**页面组件**：

- 站点页头 + 页脚（与其他前台页一致）
- 页面标题「关于我」
- 正文内容块：博主简介、可选的技能/经历列表、联系方式（邮箱 / 社交链接）

**交互与规则**：

- 内容为站点内置的静态文案，本期不做后台可视化编辑

#### 3.1.4 404 页

**功能描述**：兜底页，用于任何找不到的内容。

**页面组件**：

- 提示文案「页面不存在」
- 返回首页链接

**交互与规则**：

- 覆盖场景：路径不存在、文章不存在、文章存在但仍是草稿

### 3.2 博主管理后台

#### 3.2.1 管理员登录

**功能描述**：博主凭账号密码进入后台，是后台的唯一入口关卡。

**页面组件**：

- 页面标题（如「管理员登录」）
- 账号输入框
- 密码输入框（掩码显示）
- 登录按钮
- 错误提示区

**交互与规则**：

- 凭据正确 → 进入仪表盘，并保持登录状态（关掉浏览器再打开仍免登录）
- 凭据错误 → 停留在登录页并显示失败提示，不区分「账号错」还是「密码错」，且不清空已填的账号
- 未登录访问任何后台页面 → 重定向到登录页
- 已登录访问登录页 → 直接跳转仪表盘
- 账号与密码由服务端环境配置提供；修改后需重新初始化管理员数据

#### 3.2.2 仪表盘

**功能描述**：博主登录后的落地页，一眼看清内容家底。

**页面组件**：

- 后台导航（含「仪表盘」「文章管理」「退出登录」）
- 统计卡片 ×3：**文章总数**、**已发布**、**草稿**
- 最近文章列表：最近创建/更新的若干篇文章（标题 + 状态 + 时间），点击进入该文章编辑页

**交互与规则**：

- 统计数字实时反映当前数据状态，不使用缓存值
- 空库时统计显示 0，最近文章区显示空状态

#### 3.2.3 文章管理

**功能描述**：文章的全生命周期管理——查看列表、新建、编辑、删除。

**页面组件（列表页）**：

- 后台导航
- 「新建文章」入口按钮
- 状态筛选：全部 / 已发布 / 草稿
- 文章列表：每项显示标题、状态（已发布/草稿）、发布时间（草稿显示「—」）、操作按钮「编辑」「删除」
- 删除二次确认弹层，提示中带上文章标题，确认后才真正删除
- 空状态：无文章时给出提示，并提供「去新建」入口

**页面组件（新建 / 编辑表单页）**：

- 标题：单行输入，必填
- 正文：Markdown 多行输入，必填
- 状态：已发布 / 草稿 二选一
- 「保存」按钮 + 「返回列表」入口
- 校验失败时保留用户已填内容，并给出字段级提示
- 编辑页需回填该文章的现有内容

**交互与规则**：

- 保存成功后返回列表页，列表数据同步更新
- 文章访问地址由标题自动生成；标题重复时自动去重（如追加序号），博主无需手填、也不可手改
- 首次将文章置为「已发布」时记录发布时间；后续编辑不改变该时间
- 草稿转为已发布后立即对访客可见；已发布改回草稿后立即对访客不可见
- 删除不可恢复，必须经二次确认

## 4. 非功能性需求

### 4.1 响应式设计

站点在手机、平板、桌面三类设备上均需正常可用：无横向滚动条、无内容溢出、无被遮挡或点不到的按钮。验收基准宽度为 **375px（手机）/ 768px（平板）/ 1440px（桌面）**。

断点划分：

- 手机：< 768px
- 平板：768px – 1023px
- 桌面：≥ 1024px

各页面适配要求：

| 区域 | 手机（375px） | 平板（768px） | 桌面（1440px） |
| --- | --- | --- | --- |
| 前台页头导航 | 收起为汉堡菜单，点击展开 | 完整横向导航 | 完整横向导航，与内容区对齐 |
| 首页文章列表 | 单列卡片 | 单列卡片 | 单列卡片，内容区居中限宽 |
| 文章详情正文 | 单列，左右留 16–24px 边距 | 单列居中，限宽约 720px | 单列居中，限宽约 720px |
| 关于我 | 单列堆叠 | 单列居中 | 单列居中 |
| 后台导航 | 收起为顶部栏 + 抽屉菜单 | 抽屉菜单 | 左侧固定侧边栏常驻 |
| 后台文章列表 | 卡片式堆叠（字段纵向排列） | 卡片式堆叠，或紧凑表格 | 表格，含列头与操作列 |
| 登录表单 | 占满可用宽度 | 居中固定宽度卡片 | 居中固定宽度卡片 |
| 交互元素 | 可点击区域不小于 44×44px | 同左 | 同左 |
